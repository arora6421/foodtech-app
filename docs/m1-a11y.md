# M1.7 accessibility: WCAG 2.2 AA audit

Target: WCAG 2.2 AA, plus our own bar of 44 px touch targets. Checked on **production builds**.

## How it's checked (repeatable)

- **`node scripts/a11y-audit.mjs <label>`** drives headless Chrome through every screen and sheet
  (Welcome, Craving, Diet sheet, Deck, Match, hand-off sheet, Alternative, Saved, Saved detail) at
  three viewports: phone 390×844, WCAG reflow width 320×568, and **a phone at 200% zoom (195×422)**.
  On each: axe-core (WCAG 2.0/2.1/2.2 A + AA rules); content past the screen edge; text cut off or
  spilling out of its box; targets under 24 px (2.5.8 AA) and under 44 px (our bar); a Tab walk
  checking every stop has a visible focus indicator and isn't covered (2.4.7, 2.4.11). Reports in
  `docs/a11y/`.
- **`src/app/services/contrast.test.ts`** computes every text and icon colour against every surface it
  sits on, including all 16 dish tints, by reproducing the browser's `color-mix(in oklab, …)`. axe
  can't judge contrast through the paper-grain texture (it reports "needs review"), so this test is
  the authority for 1.4.3 / 1.4.11.
- **`src/app/design/cardTitle.test.tsx`** checks, against the real font metrics, that descenders are
  never clipped on the deck card.
- Component tests cover keyboard operation of the deck, focus management, announcements, reduced
  motion, and the error boundary.

## Result

**Before:** everything below: layout problems at 200% zoom on the Deck, Match and Saved screens,
plus two contrast failures visible on every phone. (`docs/a11y/audit-before.json` was recorded before
the text-clipping check existed, so it under-counts; the table is the complete list.)
**After: 0 issues** on every screen at all three viewports; contrast passes on all 16 tints.

| Found | WCAG | Fix |
|---|---|---|
| Paprika spice word, chillies and YES stamp on darker dish tints: 3.84:1 (10 of 16 tints under 4.5:1) | 1.4.3 | Red on tints uses a deeper paprika `#9e311e` (≥ 4.75:1 on all 16); the brand accent `#b53a25` stays on paper (5.0:1) |
| 200% zoom: "Decide for me" and Save pushed off-screen; YES/NOPE squeezed to 26–37 px | 1.4.10, 2.5.8 | Under 300 px wide, action rows reflow: deck buttons 2 + "That's the one" below; Match actions wrap; "Or try" tiles stack; top bar wraps |
| 200% zoom: deck-card name, tags and venue truncated | 1.4.10 | Under 300 px the card's rows wrap in full and the card scrolls if needed (the fixed layout holds at normal phone sizes) |
| 200% zoom: Match/Saved dish name wider than its box ("shawarm…"), price past the edge | 1.4.10 | Display heading scales down only on very narrow screens (46 px on phones, ≥ 28 px); price line can wrap |
| Tag separators made "CREAMY · SAUCY · WARM" one unbreakable word | 1.4.10 | A normal space after each dot, so lists can wrap |
| Saved tiles at 200%: text column collapsed to 1 px | 1.4.10 | Under 300 px the decorative thumbnail hides and the action goes under the text |
| Card keyboard hint read twice (as description and as content) | — (quality) | Hint is the description only |
| Settings rows read "DIET NONE" | — (quality) | Named "Diet: None", "Budget: Any", "Eating: Either" |

Also verified: every interactive element ≥ 44 px on phone sizes; focus visible and unobscured on
every Tab stop; each new deck card announced; Match focuses its heading on arrival; sheets trap focus
and return it; reduced motion removes all travel, tilt and staggered reveals.

Hardening done alongside: a stored session that can't be replayed is dropped instead of breaking every
reload; the app works with browser storage blocked (nothing is remembered, nothing breaks); a screen
that throws shows a recovery message ("Something went wrong" · Start again) instead of a blank page;
debug and review tools don't exist in production builds.

## Not automatable: please check on your phone

Screen readers can't be driven from here. A 10-minute pass with **VoiceOver** (iPhone: Settings →
Accessibility → VoiceOver) or **TalkBack** (Android):

1. **Welcome:** swipe right through; you should hear the name, the headline, then "Just me".
2. **Craving:** mood buttons announce "selected / not selected"; the settings rows read "Diet: None".
3. **Deck:** the card reads dish, cuisine, venue, price, time, distance and spice level, then the hint.
   Double-tap "Yes"; the next card should be announced ("Card 2. …").
4. **Match:** focus lands on "Match found"; the ticket reads dish, venue, price and the reasons.
   Open "Order": focus moves into the sheet, and back to "Order" when it closes.
5. **Zoom:** with the browser at 200% (or Display Zoom / large text), nothing should be cut off.

Anything that sounds wrong, tell me what was read and where.
